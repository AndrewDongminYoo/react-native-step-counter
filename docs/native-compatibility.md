# Native compatibility

## Supported range and migration

This source revision declares React Native `~0.88.0`, React `~19.3.0`, and the New Architecture.
The minimum and current CI validation point are both RN `0.88.0` / React `19.3.1`; accepting patches within those minor lines does not mean every patch has been tested.
Future RN minor versions require a separate consumer validation before widening the peer range.

The former `>=0.71.0` declaration was inaccurate: the Android implementation imports `BaseReactPackage`, which RN 0.71 does not provide, and iOS requires generated TurboModule interfaces.
This corrects the compatibility declaration without adding a legacy implementation.
Consumers on RN 0.71–0.87 must upgrade their app to RN 0.88 and its matching React/toolchain before adopting this revision, or remain on their existing package revision with compatibility assessed independently.
Do not suppress peer errors or disable the New Architecture as a migration strategy.
Use the [official upgrade guidance](https://reactnative.dev/docs/upgrading) for the app migration.
The package version remains unchanged in this PR; publication and release policy are separate work.

The clean consumer is generated by `tests/compatibility/create-consumer.sh` using CLI `20.2.0` and the official RN `0.88.0` template.
It installs the result of `yarn pack`, not the source workspace, and checks both platform autolinking entries before compilation.
Native workflows retain the existing example integration and native regression tests, then compile that standalone consumer.
The iOS workflow additionally runs a [bridgeless event replay](../tests/ios/README.md#bridgeless-consumer-replay) in its own disposable simulator, with synthetic Core Motion input and the packed library’s real generated event transport.
The RN template owns its toolchain versions; the workflow records resolved values and Xcode/SDK versions so runner changes remain visible.
Check the exact PR-head native workflow logs for actual successful combinations; this table describes the build contract, not evidence of a future CI pass.

## Verification limits

The build matrix covers compilation and packaging; the additional iOS replay checks generated callback delivery and subscription ownership using synthetic sensor input.
Neither establishes physical-device walking accuracy, energy use or background delivery.
No claim is made for RN 0.71–0.87, future RN minor versions, the legacy architecture, Expo Go, release signing, or background/app-killed tracking.
Expo development builds have not been validated by this matrix.
The New Architecture requirement follows the native codegen integration; the [RN 0.88 release](https://reactnative.dev/blog/2026/10/19/react-native-0.88) documents the current native packaging changes.

To reproduce with a new disposable directory outside the repository:

```bash
bash tests/compatibility/create-consumer.sh /absolute/new/compatibility-consumer
```

Then run the platform build steps from `.github/workflows/native-android.yml` or `.github/workflows/native-ios.yml` with the required SDKs installed.
Keep the generated consumer and adjacent tarball as diagnostic output until the run is settled.
